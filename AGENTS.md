```
npm start          # build + launch electron (ALWAYS a cold start)
npm run typecheck  # tsc --noEmit (strict)

```

Launch for verification from an agent shell: `Invoke-CimMethod Win32_Process Create` with `cmd /c cd /d <dir> && node_modules\.bin\electron.cmd . 1> "%TEMP%\mr-out.log" 2> "%TEMP%\mr-err.log"`. Plain Start-Process children get reaped by the sandbox.

## Non-Negotiable Invariants

1. One immortal `<audio>` element owned by `PlayerService` — created once, never destroyed. Views are overlays; navigation must never touch playback internals.
2. No dev server, no HMR. Every run is build + cold launch.
3. rAF clock drives sync; never rely on `timeupdate` alone.
4. Bind event listeners exactly once at boot. Views subscribe to buses (`player.bus`, `appBus`, `libraryStore`); nothing unbinds on navigation.
5. Strict TypeScript, zero comments in code, no emoji.
6. All IPC passes through `preload.ts` via typed `MrApi`; renderer has no Node access.
7. `media://` protocol serves ONLY whitelisted roots (settings.musicDirs + art cache dir) with path containment checks and Range support.
8. Custom properties that animate colors must be registered via CSS `@property` (see `--acc-*`).

## Conventions

- **Aesthetic Contract ("Moonlit Drift")** — `tokens.css` is the single source of truth:
  - Backgrounds are always near-black voids (`--void-0..2`); never pure black, never light.
  - Ink (text/lyrics) is always high-luminance (≥88%) tinted by the active song's hue — personality comes from hue + glow (`--lyric-glow`), never from dark ink or saturated fills.
  - Interactive accents flow through registered `@property` colors `--acc-a/b/glow`, crossfading ~700ms; priority chain: playing song > moonlight defaults. Hover never recolors the UI (the palette reaction was removed 2026-08-30) — hover keeps its audio preview and a static CSS highlight only.
  - Hover states are *diluted* accent mixes (~55% toward white); selected/playing states use full-strength accent plus a solid left bar — hover ≠ selected by construction.
  - Typography: Sora for all display/body text (weights 300/400/600), IBM Plex Mono only for numerals/timestamps. Lyric sizes multiply `--lyric-scale`.
  - Motion: drift easing `cubic-bezier(0.16, 1, 0.3, 1)`, long durations (400–700ms); motion is flag-gated (`fx.motion/carousel/pulse/morph/lantern`) and writes only transforms/custom properties. Band-reactive pulse rides opacity/scale, never filter functions; blurred layers drift via compositor translate, never background-position.
  - Forbidden: emoji as UI icons, glassmorphism cards, purple→blue gradient clichés, neon saturation, springy bounce easing.
- Accent system: everything interactive consumes `--acc-a/b/glow`; settings modal sections mirror it too.
- Musical reactivity consumes `core/moments.ts` onsets (adaptive flux threshold, 200ms rate limit, strength-scaled) and obeys `fx.pulse`; current consumer: marker mote bursts (later: hover pops, glow kicks, Phase 7 playhead particles).
- Cards use `content-visibility:auto` + `contain-intrinsic-size`; motion writes only transform/custom props (`--cs` scale, `--py` drift).
- Expanded view modes — Art / Art + Lyrics / Lyrics Only — via dots above the transport, keys 1/2/3, or art/title cycling; persisted as `nowPlayingView`; lyric modes require `hasLyrics` (locked dots shake). Lyrics wheel-park pauses sync; idle snaps home.
- Search = oracle popup only. Browse render is never filtered by query state.
- Settings modal: two internal views (`#settings-home` ⇄ `#libraries-view` drill-down). Motion = master switch + three granular flags (`motionCarousel/Pulse/Morph`); a fourth (`motionEmbers`) returns with Phase 7. Lyrics = auto-fetch, save-beside-gate on `.lrc` writes, S/M/L text scale (`--lyric-scale`), separate S/M/L timeline-lyric scale (`--timeline-lyric-scale`), lyric alignment (left/middle/right), and lyrics pane side (right/left) for the expanded view.

## Hard-Won Lessons

- Never derive hue from low-chroma tones — near-black/near-white colors carry mathematically arbitrary hues (neutral black landed on 0° = red and turned a blue cover's UI red). Tone selection is `selectTone` in `palette.ts`: chroma × √prominence behind a neutral-vividness floor; fully neutral palettes fall back to moonlight (2026-08-27). And a floor can only judge tones the extractor guaranteed to exist — population-only extraction let neutrals lock out ultraviolet's purple/pink entirely (2026-09-12); extraction is two-lane (population + chromatic reserve) with per-tone pixel shares.
- Shared CSS classes couple unrelated surfaces — resizing `.song-thumb` to 64px for song rows silently broke the oracle's 44px columns (text painted over thumbnails). Scope overrides (`.oracle-row .song-thumb`) when one chip serves different-density surfaces.
- Verify paint order whenever a stacking context appears — the ember canvas at root `z-index: -2` painted behind `#browser` (z 0) and was invisible. Place surfaces inside the stack they belong to and re-check every `z-index` above them.
- New visual effects must register with the motion-flag system at birth — the master switch silently stopped covering newer surfaces until audited. Policy: chrome (static washes, ≤700ms color crossfades, hover tints) is always allowed; anything looping, entering, or audio-reactive is gated.
- Motion semantics shape perception — downward drift reads as snow, not stars. State grammar: solid/framed = committed, dotted/transient = preview.
- Canvas particles (they returned — lantern motes): pre-allocated ring buffer, pre-rendered sprite variants rebuilt only on accent change, dirty-rect clearing (union of previous + current bounds), park the rAF when nothing is alive, and keep floor/ceiling bounds on any music-reactive behavior.
- Fading a canvas gradient to `rgba(0,0,0,0)` dims the color through black on the way out — the circular "shadow" artifact. Fade to the same color at zero alpha, or paint through an alpha mask with `source-in` (the lantern halo and SVG tint share this path).
- Platform cursor law (banked from the Phase 3 attempt, 2026-08-29): Electron drag regions (`-webkit-app-region: drag`) suppress the cursor to NOTHING — no arrow, no fallback; Chromium suppresses custom cursor sprites whose bitmap extends past the window's client bounds (top/bottom bars die first); `cursor: image-set()` is unsupported and silently invalidates the declaration; PNG data-URIs beat SVG for cursor bitmaps; unquoted `url()` may not contain commas/semicolons. Verify cursor regressions by reading the system cursor handle (`GetCursorInfo`) or CDP computed styles — never by eye alone.
- Entrance animations with `animation-fill-mode` that animate `transform` override the cascade transform they sit on — keyframes must compose the same custom-property scales (song-in lesson: `scale(calc(var(--cs,1)*var(--hs,1))) translateY(...)`), or rows snap when the fill releases.
- `:root`-transitioned `@property` colors make computed reads at write time return the transition's START value — snapshot-once watchers run permanently one accent behind. Chase the window: re-read per frame for ~800ms after any accent write and rebuild on change (lantern accent chase).
- Band-reactive CSS filter functions (`saturate(calc(...var(--bass)))`, drop-shadow radii) re-rasterize the entire filtered layer on every band update, and `background-position` animation on a blurred layer repaints + re-blurs at 60fps forever. Drift via compositor translate; pulse via opacity/scale; keep blur/saturate static per palette.
- New settings keys MUST be added to the `settings:update` whitelist in `main.ts` or they silently fail to persist — controls feel dead. Verify settings round-trips via CDP (`--remote-debugging-port` + Runtime.evaluate), never by eye.
- The pointer event's own `target` is a free hit test — keep `elementFromPoint` out of frame loops; re-check drag zones on move/resize plus a MutationObserver on the toggling element.
- Drawn-cursor latency model: same-frame sampling + present ≈ 1–2 refreshes, and it inherits every main-thread stall. Drag regions force the native arrow even under `cursor: none` + canvas — fullscreen/maximized drops the drag strip; windowed keeps it (accepted trade).
- An animated element with a drop-shadow (or any blur-class filter) repaints its blur EVERY frame, and the cost scales with layer area — the marker art swap grew the layer ~19× and took the frame budget with it. Static filtered elements rasterize once; never animate filtered layers without measuring.
- Art-asset raster pipelines: crop at native resolution before scaling (one-step big downscales alias badly — use repeated halved steps with high smoothing); floor the alpha channel in bounds scans (invisible noise pixels inflate crops); convert black-background art via luminance-to-alpha, corner-sampled to detect.
- Projecting world-space attendants (motes) around a billboard anchor (the star): the anchor's own screen offset lives inside the projection — subtract it (`off - (uCenterPx - uResolution*0.5)`) or the formation's orbit center lands at twice the anchor's offset from the canvas center. It is exactly zero at screen center, so center-only tests are structurally blind to it; regression-test off-center (MKII suite check 5b).
- Quantizing motion values coarser than a device pixel of visible effect manufactures its own jank: the river rounded card scale to 0.01 steps (5.2px pops on a 520px card) and at slow scroll the true scale sat on a rounding boundary, flipping every frame (measured: 19 pops, median 1 frame apart — the owner's "visibly resized every few frames"). Round position to the device-pixel grid; never round scale/tilt/opacity. Continuous writes cost nothing — Layout/Style/Paint measured 0/0/0 — and the redundant-write guard still skips idle work. Universal law, not display-tuned: the pops existed at every refresh rate; high-refresh screens only show them sooner.
- A `floor()`-indexed table fast-path (`if (idx <= 0) return 0`) swallows the whole first step — every distance below TABLE_STEP pins to the base value and pops at the boundary (the v2 river's 7px jump at every song boundary). Interpolate from `table[0]`; and diagnose with rendered rectangles (`getBoundingClientRect` per frame), not internal variables — the position was provably smooth while the pixels jumped.
- Per-frame motion assertions need a velocity-relative bound (Δ ≤ |Δpos| × slot + tolerance): an absolute threshold flags legitimate fast scrolling, because wheel notches accumulate to ~2 slots/s of perfectly smooth travel. A pop is motion exceeding the position's own travel.
- CSS `pointer-events: none` inherits to children — a hit layer inside a none surface must declare `pointer-events: auto` itself. Symptom: every input over the layer is dead while siblings with explicit `auto` (cards) still work.
- A color fix must clear a VISIBILITY bar at production scale, not just a correctness bar: a ±15° family hue band on an 11px star with 1–3px companions is invisible — the pipeline was provably correct (24-check suite, pixel-sampled deltas) and pointless (owner verdict: zero difference). Measure the perceptual delta at production scale BEFORE building the machinery; "the albums aren't that big of a deal" is a design verdict, not a tuning problem.

## Environment Gotchas (this machine)

- NEVER write files via PowerShell `[IO.File]::WriteAllText` without `-Encoding utf8` — default encoding corrupts non-ASCII (en-dashes, middots) to `?`. Prefer the file-edit tool; if bash replace is required, keep payloads ASCII-only or add `-Encoding utf8`.
- PowerShell here-strings: `@'` must be immediately followed by a newline.
- Edit-tool anchors fail on invisible whitespace — retry with shorter unique substrings, then fall back to ASCII-only bash `.Replace()`.
- Substring surgery on `index.html` (IndexOf→Substring splices) has swallowed sibling elements before (`#search-oracle` vanished this way). After any structural HTML splice, grep for every known id before building.
- After killing electron: `Get-Process -Name electron | Stop-Process -Force; Start-Sleep 2` before relaunch.
- **Visual verification law (Movement X):** the owner's left monitor carries a Windows 11 secondary taskbar that is an always-on-top overlay reserving NO work area — it can cover an app's bottom edge on the physical screen while every in-app instrument reports full visibility. The timeline "invisible/inconsistent" reports of 2026-09-06 were this. Verify bottom-edge and full-screen visuals in this order: (1) renderer truth — launch electron with `--remote-debugging-port=9222` and read `Page.captureScreenshot` with a clip, decoding the PNG in node (zlib + per-row unfilter) to sample real pixels; (2) computed styles prove recipes but never paint; (3) physical screen only via DPI-aware capture (`SetProcessDPIAware` + `CopyFromScreen`) — non-DPI-aware screen grabs return scaled lies on multi-DPI setups. Eyeballed screenshot crops prove nothing; instrument everything.
