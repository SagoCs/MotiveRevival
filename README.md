# MotiveRevival

A celestial-atlas music player for Windows. Browse your library as drifting constellations of album art, summon any song with a keystroke, and watch the interface breathe with the music.

---

## Vision

A local music frontend that feels **cosmic, aetherial, and fantastical** — built around three pillars:

- **Universal search, always on** — start typing anywhere; fuzzy, accent-blind matching across songs, artists, and albums. `Esc` cancels, `Enter` summons.
- **osu!-style browsing** — a momentum carousel of rounded art cards that breathe with scroll velocity; click an album to descend into its songs.
- **A living interface** — each album's dominant colors wash the stage; gradients and glows pulse with live bass/mid/treble energy; synced lyrics will complete the picture.

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Shell | **Electron** | Native file access + Chromium audio decode (FLAC/MP3/OGG) in one runtime |
| Language | **TypeScript** (strict) | Compile-time guard against the ghost bugs of attempts #1–2 |
| Bundler | **esbuild** | Sub-second builds. No dev server, no HMR — every launch is a true cold start |
| UI | **Vanilla TS + DOM** | Zero framework magic; explicit singletons, bind-once listeners |
| Tags & art | **music-metadata** | Pure JS; no native modules |
| Fonts | Sora · IBM Plex Mono via Fontsource | Local woff2, fully offline |
| Storage | JSON index + settings in `%APPDATA%\MotiveRevival` | Instant boot for <5k-track libraries |

## Architecture Rules

These exist to permanently kill the failure modes of previous attempts:

1. **One immortal `<audio>` element.** `PlayerService` owns it from boot to quit; nothing in the app ever destroys it. Navigation is overlays sliding over playback — returning to the library cannot brick the player.
2. **`requestAnimationFrame` clock**, never `timeupdate`, drives timeline and lyric sync.
3. **Cold starts only.** `npm run build` then `npm start`. HMR-style staleness is structurally impossible.
4. **`media://` streaming protocol** with range-request support and path containment (music folder + art cache only).
5. **Event buses over teardown**: player events (`Bus`) and selection events (`appBus`) fan out to persistent views; views subscribe once at boot.


## Running

```
npm install        # once
npm run build      # bundle main/preload/renderer → dist/
npm start          # build + launch (always a cold start)
npm run typecheck  # strict TS gate
npm test           # LRC parser suite (20 cases)
```

Optional: set `MOTIVE_MUSIC_DIR` to override the music folder for a session. Default archive: `D:\Music` (changeable in-app via the sliders icon → Settings).

Keyboard: type anywhere = search · `/` focuses search · `Esc` steps back (search → overlay → detail) · `Space` play/pause · `Ctrl+R` cold reload · `F12` devtools.

- **2026-08-29 — Phase 3 v2 concept locked: "The Particle Lantern" (not yet built).** Born from a live observation: during v1, the mote canvas kept rendering in the dead zones where the cursor image vanished — because canvas pixels are never subject to OS cursor suppression. v2 inverts the architecture: the pointer is *drawn*, not declared. Zero OS cursor — `cursor: none` applied permanently through the high-specificity rule (inputs keep the native I-beam yield; the v1 flicker was our own bitmap swapping, which this design cannot reproduce). The pointer's face is one pre-rasterized sprite — the owner's SVG art, rendered once per accent into an offscreen canvas at devicePixelRatio scale, accent-tinted via source-in — stamped synchronously at the last-known pointer position every frame: one big always-on particle that never fades, guaranteeing exact pointing precision. State morphs (hover-converge, press, edge chevron) are swaps between cached sprites — same-frame, no OS involvement. The existing mote system provides the movement trail (palette memory, caps, drift). Honest trade: canvas paints on the main thread, so heavy load freezes the whole formation for a frame — masked by the soft glow + trail, and nothing native ever appears to contrast against it. Verified groundwork: the v1 mote canvas demonstrably rendered in every zone where the cursor image was suppressed (drag regions, window bounds). Owner to supply per-state SVG art; motion-flag gated as before. Build order when reopened: sprite pipeline → pointer-follow core → state morphs → trail hookup → text-yield → flag. **Drag spike verdict (2026-08-29, same day): the Win32 shortcut is dead.** All three native move-loop initiators — `SendMessageW(WM_NCLBUTTONDOWN, HTCAPTION)`, its `PostMessageW` form, and `PostMessageW(WM_SYSCOMMAND, SC_MOVE|HTCAPTION)` — were delivered successfully to the frameless window (verified by return values and koffi FFI) during physically-driven drags, and Chromium ignored every one: the native move loop never engaged, the window never moved. Manual repositioning (setBounds polling, prototyped earlier) is therefore the *only* topbar path for v2; the alternative is living with the native arrow on the drag strip. A `no-drag` "gear island" already patches the worst seam. **Decision (2026-08-29, owner-confirmed after studying osu!'s screen modes): adopt the osu! windowed-mode trade — the drag flag is removed from the top bar entirely.** The window is not mouse-draggable anymore (screen-mode settings — fullscreen/borderless/windowed — become a future rider), and in exchange the particle cursor owns every pixel of the window with no arrow, no dead zones, and no flicker. Resize via the frame's invisible edges still works. The fade-out detection for `.window-drag` zones remains in the test code and self-disables now that no drag flag exists.
- **2026-08-29 — Cursor experiment settled; native top bar restored.** After living with a minimal particle-cursor test build (throwaway `particle-test.ts`: permanent `cursor: none`, one 60px accent-tinted glow stamped at the pointer every frame, F8 toggle), the results were encouraging — the particle rendered flawlessly in every zone where v1's native cursor died, including both bars, and the chip flicker was confirmed structurally gone — but the drag-region arrow remained on the top-bar strip. Weighing the options (live with the arrow, hand-rolled dragging, or borderless fixed-size), the owner restored the native top bar: drag flag and maximize button reinstated, native double-click-maximize back. The particle test build remains in the tree behind F8 for future feel-checks, and the v2 concept note stands as the map for a proper build. Verdict of the day: a canvas cursor is immune to every suppression wall, but cannot be zero-lag; a native cursor is zero-lag but suppressed in exactly the places a music player's chrome lives. Phase 3 stays deferred until both halves of that sentence can be true at once.

## Future Direction

Movement VIII — **The Living Void** — is chartered and phased (see ledger): pointer bias (4), the usability block (5), song-state effects (6), and The Waveform Horizon (7) — a full-width, horizon-tinted waveform band above the timeline with lyrics riding over it and particles thrown by the music's own onsets. The lantern cursor (Phase 3) was built and then deferred — platform-level cursor suppression in drag regions and at window bounds — and returns only as a shelved rider. Governing language: **solid means committed, dotted means preview**; music modulates through *moments*, never loudness; everything gated by the master and granular flags.

The north star beyond VIII: signature constellations growing into a navigable constellation map of the library — possibly a spatial, non-scroll alternative browsing view (prototyped as an option, never forced) — plus waveform-envelope figures, acoustic-similarity clustering, and the frosted folder-picker in Movement IX.

Beyond the charter: the frosted folder-picker and BPM-tag metadata stay open riders, waveform-envelope constellations may one day replace the hash seed, and acoustic-similarity clustering — constellations that drift toward albums that sound alike — remains the north star for a future movement.

## Known Behaviors

- First launch after an update runs a background rescan; palettes/cards refresh moments after boot (cached index paints instantly meanwhile).
- Sorting chip labels adapt per tab but occupy fixed 96px slots so the control bar never shifts.
- Artwork thumbnails (128px) are generated at scan and regenerated on demand: a missing thumbnail self-heals on its first request and then persists in the art cache.
